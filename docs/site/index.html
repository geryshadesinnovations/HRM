Business

Business Overview

HRMS SaaS is a multi-tenant human-resource platform that lets a software vendor (the platform owner) sell HR software to many companies, each with isolated data, on subscription plans.

Who uses it

PersonaGoal
Platform Owner (Super Admin)Sell & manage subscriptions, monitor revenue and platform health, manage companies, plans, coupons, and inquiries.
Company Admin / HRRun day-to-day HR: employees, attendance, leave, payroll, and the company subscription.
ManagerApprove leave & attendance corrections for their team.
EmployeeSelf check-in/out, request leave, download payslips, manage their profile & documents.

The modules

Employees

Complete digital records, document vault, bulk CSV import.

Attendance

Self / manual / GPS / biometric, breaks, corrections, period lock.

Leave

Policies, balances, approval workflow.

Payroll

Salary structures, statutory PF/ESI/TDS, two run modes, payslips.

Billing

Plans, seats, GST invoices, coupons, dunning, Razorpay.

Owner console

Analytics, companies, plans, coupons, inquiries, impersonation.

How money flows

A company signs up → starts a free trial → picks a plan (monthly/yearly) → optionally applies a coupon → pays via gateway → an invoice is issued with GST. Subscriptions auto-renew; failed payments enter a dunning cycle and, after repeated failures, the account moves to a grace window then suspension. Data is never deleted on suspension.

User guide

User Manual

This manual covers the basics shared by everyone who logs in.

Signing in

  1. Go to the app and choose Sign in.
  2. Enter your email and password (see Test Credentials for demo logins).
  3. Super Admins land on the owner console; company users land on the dashboard.

Getting around

  • Sidebar — switches between modules you have access to.
  • Command palette — press ⌘K / Ctrl+K (or the Search button) to jump to any page or find an employee instantly.
  • Theme — toggle light/dark from the top bar.
  • Notifications — the bell shows unread counts; payroll, leave, and billing events appear here.

What you can see

Menus and buttons adapt to your role and your company's plan. If a module isn't in your plan, or you lack a permission, the related pages are hidden.

Owner

Super Admin Guide

Sign in as superadmin@hrms.test / password to reach the owner console at /admin.

Owner dashboard

Shows platform-wide analytics: total / active / trial / expired companies, MRR & ARR, active subscriptions, employee growth, recent activity, and system health.

Companies

  • View, search, and filter every company.
  • Suspend / activate, soft-delete, reset a company admin's password.
  • Impersonate (secure login-as) to support a customer — actions are issued as that company.
  • Inspect subscription history, employee counts, and usage.

Plans & pricing

Create, edit, duplicate, enable/disable plans; set monthly/yearly pricing, included seats, per-seat price, trial days, and module access. Pricing changes appear instantly on the public landing page (it reads the same data via GET /public/plans).

Coupons

Create percent or fixed-amount coupons, restrict to a plan, cap redemptions, and set validity windows. Companies redeem them at checkout. Manage at /admin/coupons.

Inquiries

Contact-form submissions from the public site land in the Inquiries inbox with status tracking (new → contacted → closed).

Company

Company Admin Guide

Sign in as admin@demo.test / password.

Onboarding a team

  1. Create departments & designations.
  2. Add employees one by one, or use Employees → Import CSV (download the template, fill, upload — you get a per-row result report).
  3. Upload documents to each employee's Document vault (versioned, private).

Attendance

  • Choose how attendance is captured: HR marks it, employees self check-in/out, GPS-tagged punches, or biometric devices (plan-dependent).
  • Register biometric devices under Attendance → Devices; the device token is shown once.
  • Review and approve correction requests.

Payroll

  1. Define salary components & per-employee structures.
  2. Set statutory rules in Payroll → Settings (PF/ESI/TDS toggles & rates).
  3. Create a run (mode: payroll only or attendance + payroll) → Process → review → Publish.
  4. Publishing locks the attendance period; Reopen if you must correct it (audited).
  5. Add bonuses/incentives/penalties as adjustments; re-process to apply.

Subscription & billing

Upgrade/downgrade plans, add seats, apply a coupon code (try WELCOME20), view GST invoices, and pay.

Daily attendance

Technical

Technical Documentation

Stack

LayerTechnology
BackendLaravel 12 (PHP 8.2+), JWT auth, Spatie permissions
FrontendNext.js (App Router, React, TypeScript, Tailwind)
DatabasePostgreSQL (SQLite for tests)
PaymentsRazorpay gateway (pluggable via a gateway manager)

Architecture

  • Domain-driven backend under app/Domains/* (Attendance, Billing, Employee, Leave, Payroll, Subscription, Notification, Platform).
  • Multi-tenancy via a BelongsToTenant trait + global scope; TenantContext resolves the active company and fails closed when unresolved.
  • RBAC on the api guard — all access is database-driven permissions, no hardcoded role checks.
  • Subscription entitlements gate modules (module: middleware) and features (feature: middleware).
  • Standard envelope: success { data, meta }, error { error: { code, message, details } }.

Key conventions

  • Money is stored in minor units (paise) as integers.
  • Sensitive identifiers (PAN, Aadhaar, bank account) are encrypted at rest and masked in responses.
  • Background work: php artisan subscriptions:sweep (lifecycle) and php artisan billing:cycle (auto-renew + dunning) — schedule both daily.

Database Schema

Every tenant-owned table carries company_id. Full details in docs/02-DATABASE.md.

Core tables

TablePurpose
companies, usersTenants and login accounts (users carry company_id + is_super_admin).
plans, modules, features, subscriptionsCatalogue + a company's live plan instance & entitlements.
employees, employee_documentsDeep records (encrypted PAN/Aadhaar/bank) + versioned document vault.
attendance_records, attendance_correction_requests, biometric_devicesPunches (geo + capture method), correction workflow, devices.
leave_types, leave_requests, leave_balancesLeave policy + workflow.
payroll_runs, payslips, salary_structures, payroll_settings, payroll_adjustmentsRuns (mode + lock), payslips, statutory config, audit adjustments.
invoices, payments, coupons, coupon_redemptionsGST invoices (discount + dunning columns), payments, discounts.

Conventions

  • UUID public keys (uuid) on most resources; integer PKs internally.
  • Soft deletes where history matters (employees, documents, plans, coupons).
  • Money columns are bigInteger minor units.

Deployment Guide

Local development

# Backend
cd backend
composer install
cp .env.example .env && php artisan key:generate
# set DB + JWT_SECRET in .env, then:
php artisan migrate:fresh --seed     # seeds Super Admin + demo company
php artisan serve

# Frontend
cd ../frontend
npm install
# set NEXT_PUBLIC_API_URL=http://localhost:8000
npm run dev
After seeding, log in with any account from Test Credentials.

Production

  1. Provision PostgreSQL; set a strong JWT_SECRET and APP_KEY; APP_ENV=production.
  2. composer install --no-dev --optimize-autoloader, then php artisan migrate --force (do not seed demo data).
  3. Configure a private storage disk for the document vault and the Razorpay keys.
  4. Build the frontend: npm run build and serve behind your host/CDN; point NEXT_PUBLIC_API_URL at the API.
  5. Schedule the daily workers (cron / Laravel scheduler): subscriptions:sweep and billing:cycle.

Maintenance Guide

Scheduled jobs

CommandCadenceDoes
php artisan subscriptions:sweepDailyTrial→active, active→grace→expired transitions by date.
php artisan billing:cycleDailyAuto-renews due subscriptions; runs dunning on overdue invoices (3 retries → uncollectible + grace).

Routine tasks

  • Back up the database and the document-vault disk regularly.
  • Rotate JWT_SECRET and gateway keys per your security policy.
  • Apply dependency updates and re-run the test suite before deploying.
  • Monitor failed payments and the owner dashboard's system-health panel.

Quality gates

cd backend && ./vendor/bin/pint --test && ./vendor/bin/phpunit
cd frontend && npx tsc --noEmit && npm run build
