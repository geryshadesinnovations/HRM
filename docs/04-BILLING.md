# 04 — Billing Engine

A **reusable, gateway-agnostic** billing layer. Admin can switch gateways without
changing business code. Initial adapters: **Razorpay, Cashfree, PayU**; **Stripe**
is future-ready via the same contract.

## Gateway Abstraction

```php
interface PaymentGateway
{
    public function createOrder(Money $amount, array $meta): GatewayOrder;
    public function capture(string $gatewayPaymentId): PaymentResult;
    public function refund(string $gatewayPaymentId, Money $amount): RefundResult;
    public function verifyWebhook(Request $request): WebhookEnvelope; // signature check
    public function parseEvent(WebhookEnvelope $e): NormalizedEvent;   // maps to canonical events
}
```

- A **`GatewayManager`** resolves the active gateway from config/DB
  (`billing.default_gateway`), so switching is a setting change.
- All gateways normalize to canonical events: `payment.captured`, `payment.failed`,
  `refund.processed`, `subscription.charged`, `mandate.revoked`.
- Amounts are always `Money` value objects (minor units + currency) — never floats.

## Webhook Flow (idempotent)

```
Gateway ──POST──▶ /api/webhooks/{gateway}
   1. verifyWebhook() signature → reject if invalid (401)
   2. persist raw into webhook_events (UNIQUE gateway,event_id) → dedupe
   3. dispatch ProcessWebhook job (returns 200 fast)
   4. job: parseEvent → apply to invoice/payment/subscription in a transaction
   5. emit domain events (PaymentSucceeded / PaymentFailed) → notifications
```

Reprocessing the same `event_id` is a no-op (already-processed guard).

## Invoicing

- Invoice numbers are sequential per financial year: `INV-2026-000123`.
- Lines carry `tax_rate`; totals computed by a **TaxCalculator** (India GST: CGST/SGST
  intra-state vs IGST inter-state, derived from company GSTIN/state).
- PDF invoices generated by a queued job and stored in S3/R2; downloadable by Company
  Admin and Super Admin.
- States: `draft → open → paid` (or `void` / `uncollectible`).

## Renewals, Failures, Retries

- Auto-renew subscriptions create an `open` invoice at period end, then attempt a
  charge (saved mandate/token where the gateway supports it).
- On failure: subscription enters `grace`, dunning notifications fire, and a retry
  schedule runs (e.g. T+1, T+3, T+5). Exhausted retries → `expired`.
- Manual renewal: customer pays the open invoice via a hosted checkout link.

## Refunds

- Full or partial; recorded as a `payments` row with `status=refunded` and linked to
  the original payment; emits `RefundProcessed`. Super Admin initiated, audited.

## Configuration (no code change to switch)

